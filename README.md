# truenas-pulse-site

Promotional site for [TrueNAS Pulse](https://apps.apple.com/app/id6759870893) — the third-party iOS client for TrueNAS SCALE.

Live: **https://truenaspulse.com**

## Stack

- [Astro 5](https://astro.build) (static, zero JS by default)
- [Tailwind CSS v4](https://tailwindcss.com) — native Vite plugin, `@theme` block holds all brand tokens
- [MDX](https://mdxjs.com) for legal pages (Privacy, Terms, EULA)
- Custom 30-line IntersectionObserver + WAAPI for scroll reveals (no JS animation library)
- [sharp](https://sharp.pixelplumbing.com) for build-time icon and OG image generation
- Bun as the package manager and runtime (swappable for Node 20+ if needed)

```
  deploy.yml     GitHub Actions — bun build → Cloudflare Pages production
```

## Local development

```bash
bun install
bun run dev          # http://localhost:4321 with hot reload
bun run check        # Astro/TypeScript diagnostics
bun run build        # static build into ./dist
bun run preview      # serve ./dist for a local production preview
```

To regenerate the favicon set, OG image, and webmanifest from the iOS app's
master icon:

```bash
bun run scripts/generate-assets.mjs
```

The script looks for `../TrueNAS-Pulse/assets/icon/TrueNAS_Pulse_AppIcon_Master_UNMASKED_1024.png`
first, then `./public/icon-master.png`.

## Copy and presentation checks

Free includes monitoring for up to 2 servers, one local monitor on the active
server, and manual snapshot creation. Pro supports up to 8 servers and adds
fleet tools, longer reporting history, and guarded administration, including
snapshot deletion, cloning, and rollback. Purchase prices are localized by the
App Store. Cloud Push is retired; current pages must not promote the relay.
Historical changelog entries remain explicitly marked as retired.

The header switches to its mobile menu below the `lg` breakpoint. Maintain
44-pixel mobile tap targets, visible keyboard focus, and Escape-to-close behavior.
The Free/Pro comparison must wrap on small screens and retain its table caption,
row/column headings, and accessible inclusion labels. The support form reminds
users to omit API tokens and passwords.

Before publishing, run `bun run check` and `bun run build`. Review the built
homepage, Pro comparison, and support page at desktop, tablet, and phone widths.
Use a fresh isolated browser profile when validating on the user's machine.
Check horizontal overflow, visible image loading, menu/Escape behavior, and
page runtime errors. Do not submit a real support message as a layout check.

## Deployment

Push `main` to Gitea `phobos/truenas-pulse-site`; its mirror publishes the same
commit to GitHub [`Phobos-cc/truenas-pulse-site`](https://github.com/Phobos-cc/truenas-pulse-site).
Two independent workflows build the static site:

- **Public production:** `.github/workflows/deploy.yml` builds with Bun and uses
  [`cloudflare/wrangler-action`](https://github.com/cloudflare/wrangler-action)
  to run `pages deploy dist --project-name=truenas-pulse-site --branch=main`.
  Cloudflare Pages serves **https://truenaspulse.com**. GitHub stores the
  `CLOUDFLARE_API_TOKEN` secret; the account ID is configured in the workflow.
- **Homelab origin copy:** `.gitea/workflows/deploy.yml` runs on the self-hosted
  runner, builds with Bun, and rsyncs `dist/` to LXC 132 (`192.168.0.93`) at
  `/var/www/pulse-site/`. It updates Caddy ownership and inline-script CSP hashes,
  validates/reloads Caddy, and smoke-probes six origin pages with the production
  Host header. Gitea stores `DEPLOY_SSH_KEY` and `DEPLOY_HOST` secrets.

The legacy `https://pulse.phobos-cc.be` URL redirects to public production. A
successful Gitea origin deployment alone does not confirm that Cloudflare Pages
published the change. Verify the GitHub Actions run and live public pages before
claiming a completed publication; preserve the source commit and build hashes.
Back up `/var/www/pulse-site/` and `/etc/caddy/Caddyfile` before changing the origin.
